## 2027.4.0

发布时间: 2026 年 5 月 15 日

若升级发生问题, 请加 [Quicker 交流群 ](https://getquicker.net/KC/Kb/Article/904)联系地球解决

1. 铺路 - 新增用户数据升级机制 - 为新功能/重构铺垫, 首先请看下方示意图:

![🍟 升级提示窗口](/img/docs/release-notes-2027/1778759911140-2ebbe9ea-61a3-42e4-8964-20a9a4c49bae.png)

在本次升级中, 如果您从旧版本升级而来, 在首次打开新版本时, 您会看到上面的提示窗口,

当您看到上述提示后, 意味着该新版本会优化已有的用户数据结构, 使得软件更好地运行.

**比如**, 在本次 `2027.4.0` 版本中, 地球优化了图标的存储方式, 在之前的版本中, 如果您给动作设置的图标太高清 (例如 4K 分辨率大图标 🤔), 那么加载图标的速度会变慢, 有 2 点原因:

1. 早期设计不足, 图标使用 base64 文本保存, 读取时需要额外 base64 解码, 产生额外开销, 升级以后会直接使用二进制 blob 方式保存在数据库 (保存到了崭新的字段, 新版本 Quicker 社区版 会从新的字段读取图标数据), 因为是二进制直接保存, 读取后无再需 base64 解码, 速度更快.
2. 再大的图标也不会被压缩, 导致原图保存, 但实际上我们只需要最大保存 128 x 128 像素的图标就足够了, 升级后会完成压缩 (规整为最大 128 x 128 像素, 且保留原图比例)

您应该可以从上述看得出来, 这是一次用户数据的有感升级, 因为一旦升级后, 图标数据转到了新的数据库字段中存储, 完成转移, 那么旧版本 Quicker 社区版 就无法读取了, 会产生未知的错误, 所以在升级后, 不建议用回旧版本, 如果您在升级后遇到了曾经没有的问题, 那么这个时候就要及时联系地球, 等待地球出新版本.

**其他小贴士:**

1. 在提示页面, 在点击 “升级并启动” 按钮前, 若您不想继续升级, 您可以打开 系统“活动监视器” 强退 Quicker.

![1️⃣](/img/docs/release-notes-2027/1778760840410-74404787-84ae-4ebe-a8c1-a726d3bb87ab.png)![2️⃣](/img/docs/release-notes-2027/1778760858532-b9756b8a-8cee-461a-869c-85cda13b80c3.png)

2. 已经点了 “升级并启动”, 已经在处理中状态了/突然断电了/失败报错了 等任何意外发生时, 安全退回旧版本的方法:

在 Quicker 社区版 正式开始升级前, 会完整备份旧版本的用户数据, 见下图:

![](/img/docs/release-notes-2027/1778761150031-82b3341e-94bd-4f18-a0e6-cc5d6c940139.png)

```plain
/Users/darcy/Library/Application Support/QuickerCommunityEdition/
```

所以说, 在任何问题发生时, 我们只需要删除不正确的 `userdata.sqlite` 文件, 然后拷贝 `backup`文件夹中的一份到外面来, 重命名为 `userdata.sqlite`, 然后回到旧版, 就完成恢复了.

2. 优化 「选择文件」「选择文件夹」模块 UI - 目前发现似乎原生窗口<u>反而</u>可以置顶了, 所以需要置顶的情况默认使用原生 UI, 在不需要置顶的情况下使用 经典 UI - 同时修复该窗口可能为 App 的模态窗口的问题.
3. 优化「Quicker 操作」模块 - 该模块的下拉补全应该是此前“项目错误显示”最多的一个模块了, 之前 Quicker 社区已经大量优化编辑器中 <u>受支持的模块和参数</u> 显示的优化, 主要目的是: “如果这个模块参数不支持, 宁可不显示”,  本次优化了单独优化了一下「Quicker 操作模块」, 已只显示可用的操作.
4. 优化 Python 表达式 (以 **@=** 开头, 2027.3.0 版本中首次加入) 编辑时的补全体验, UI 界面的迟钝感不再明显(主要体现在首次键入时), 之前的补全逻辑是在 UI 线程执行的, 现在已经放入了后台线程 (后台补全完成后 -> 再行通知主线程显示 UI 补全框).
5. 回归与优化 - 错误提示窗口回归了, 并改进 UI, 窗口更紧凑, 并会提示问题的来源 (软件 BUG 或 动作 BUG)
