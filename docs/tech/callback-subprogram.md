---
title: 回调子程序
sidebar_position: 2
---

子程序除了被「调用」，还能被**回调**：某个步骤在后台产生事件（文件变化、服务端推送），就把子程序排进队列，等当前步骤结束后执行。

## 哪些模块会产生回调

| 模块 | 事件 |
| --- | --- |
| 文件系统监听 | 监听的文件/目录发生变化 |
| HTTP 请求（服务端推送模式） | 服务端推来一条事件 |

其他模块不会产生回调。

## 什么时候执行

- 每个步骤执行完都会检查一次队列，有回调就执行。
- 等待步骤期间也会执行，所以不会因为「正在等待」而卡住回调。
- 回调**和主流程在同一个线程里串行执行**：回调跑得久，主流程也会跟着慢。

## 作用域与限制

| 项目 | 说明 |
| --- | --- |
| 能拿到的数据 | 只有声明为输入参数的变量 |
| 主流程变量 | **看不到** |
| 子程序的输出 | **拿不到**，只有成功/失败会传回 |
| 子程序名写错 | 该步骤直接失败，动作中止 |

## 中止

中止标志对主流程和回调都生效。注意：在**子程序内部**用「停止」步骤默认只结束这个子程序，不会连带结束调用方；需要整体停止请用「强制停止」。

## 和「运行动作」的区别

| | 回调子程序 | 运行动作 |
| --- | --- | --- |
| 执行方式 | 同一线程，排队，同步 | 新开一次动作运行 |
| 数据传递 | 输入参数 | 输入参数 / 子程序签名 |
| 输出 | 拿不到 | 勾选等待时可以拿到 |
