社区版同时支持 macOS 和 Linux，但两个平台的能力并不对等，Windows 版的动作也不能直接拿来跑。这一页说清楚「什么能用、怎么判断、哪些注定要改」。

## 动作：Windows 版导入后基本要重写

- 从 Windows 版导入的动作**可以打开、可以看**，但很多模块在社区版里没有等价实现。
- 导入的步骤不会消失，只是那些模块在社区版里跑不通，实际运行会报错或什么都不做。
- 所以：**社区版的动作用户基本需要自己编写**。导入更多是「拿来看原来的逻辑」。

## 模块：能不能用，看「模块实现进度」

[模块实现进度](/xaction/module-progress) 里每个模块有两列状态：

| 列 | 含义 |
| --- | --- |
| 实现度 | 该模块的参数实现了多少。没实现的参数在界面上会被**隐藏**，所以你「找不到某个参数」通常不是 bug |
| Linux | ✅ 两平台可用；❌ 只在 macOS 可用（Linux 上模块直接隐藏） |

判断一个动作能不能跨平台：把用到的模块挨个对照这张表，只有两个平台都是 ✅ 才行。

## 已知的兼容缺口

| 缺口 | 影响 |
| --- | --- |
| 变量类型 | 键盘、鼠标、枚举、表单、对象等类型在导入时统一降级成「动态对象」，类型信息丢失 |
| 子程序 | 只按**本地名字**匹配，不会从网络补全缺失的子程序 |
| 平台专属模块 | AppleScript、Vision、辅助功能、浏览器控制这类只有 macOS 能做，Linux 上没有替代方案 |

## 平台差异的实际影响

| 场景 | macOS | Linux |
| --- | --- | --- |
| 全局键盘/鼠标监听 | 需要「辅助功能」授权 | 需要 X11 会话（Wayland 不支持） |
| 截图 / OCR / 找字 | 系统能力齐全 | 无 OCR；截图、找图、找色可用 |
| 浏览器自动化 | 支持（AppleScript） | 不支持 |
| 输入法切换 | 支持（仅 ABC / 简体拼音） | 不支持 |
| 系统事件触发 | 13 种事件 | 只有「应用被激活」 |

## 写跨平台动作的建议

1. 只用两平台都 ✅ 的模块。
2. 路径一律写 `/`，不要依赖反斜杠兼容。
3. 需要「只有某个平台才做」的逻辑时，用条件步骤判断系统，而不是指望模块自己容错。
