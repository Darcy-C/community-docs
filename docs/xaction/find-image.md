title: 屏幕找图 / 找色 / 找字

---

在屏幕（或指定窗口/区域）里查找图片、颜色或文字，返回命中坐标。动作里常见的「点这里」就是这么来的。

| 能力 | macOS | Linux (X11) |
| --- | --- | --- |
| 找图（截图模板匹配） | ✅ | ✅ |
| 找色 | ✅ | ✅ |
| 找字（OCR） | ✅ | ❌ 隐藏（依赖 Vision） |

## 三种查找方式

| 方式 | 输入 | 说明 |
| --- | --- | --- |
| 查找图片 | 图片文件或图片变量 | 模板匹配，可设相似度 |
| 查找颜色 | 颜色值 | 内部按 1×1 图片走同一套匹配 |
| 查找文字 | 文本 | 用系统 OCR 识别后逐行比对 |

**查找文字**的实现是：先对目标区域做 OCR，再按「第一个匹配到的行」定位，「匹配序号」 从 0 开始。中文/多语言识别能力取决于系统 OCR。

## 目标范围

- 所有屏幕、当前窗口、指定区域。区域模式不会跨屏幕。
- Retina 屏会按缩放比换算坐标，返回的坐标是**逻辑坐标**，可以直接喂给鼠标模块。

## 输出

| 输出 | 说明 |
| --- | --- |
| 「第一个匹配点」 | 第一个命中点，格式 `x,y` |
| 「所有匹配点」 | 所有命中点 |
| 「匹配序号」 | 命中的行/图索引（找字时是 OCR 行号） |

匹配失败时步骤报错：`屏幕识图没有找到匹配`。

## 注意

- 内部带**重试**（约 300 ms 一次），所以「等界面出现再找」可以先不 sleep，让它自己重试到超时。
- 找图对缩放/主题颜色敏感：换显示器、改分辨率、切暗色主题都会导致匹配失败，模板图要重新截。
- 找色比找图快得多、也稳，能用颜色就用颜色。

:::tip

需要「找到再点」的完整流程，直接用步骤里的「屏幕找图」+「鼠标操作」，或者看看「控制界面元素」模块是否更适合——它按辅助功能树查找，不依赖像素。

:::
