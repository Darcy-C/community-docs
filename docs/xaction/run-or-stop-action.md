---
title: 运行或停止动作
sidebar_position: 20
---

运行另一个动作、停止正在运行的动作、或查询某个动作当前有几个实例。

## 操作

| 操作 | 需要的目标 | 说明 |
| --- | --- | --- |
| 运行动作 | **动作 UID**（32 位） | 不支持用动作名 |
| 停止动作 | UID 或动作名 | 名字要完全一致 |
| 运行当前动作 | — | 重新启动自己（新实例） |
| 停止其他实例 | — | 停掉除自己以外的同名实例 |
| 获取运行中数量 | UID 或动作名 | 结果写进输出 |

:::note[为什么运行动作只认 UID]
动作数据存在 sqlite 的 `actions(action_uid unique, data)` 表里，只有 UID 有唯一索引；按名字查不到，所以「运行动作」只接受 32 位 UID。UID 可以从面板动作的右键信息里复制。
:::

## 运行时的参数

| 参数 | 说明 |
| --- | --- |
| 输入参数 | 传给目标动作，动作里用 `quicker_in_param` 取（也可以用子程序传参，见 [回调子程序](/tech/callback-subprogram)） |
| 等待执行结束 | 勾选后会等目标动作跑完，并把它的输出交回来 |
| 输出 | 目标动作的返回值 |
| 调试模式 | 以调试方式启动 |

失败时报错形如 `动作运行失败...`；「动作名称」 输出能拿到目标的标题，方便拼提示。

## 平台

macOS 与 Linux 行为一致（都走同一套 sqlite + 进程内调度）。

:::tip

需要在动作之间**传结构化的输入输出**，优先用子程序而不是「运行动作 + JSON 参数」。

:::
